# `@stagehand/runner-core`

This package starts one Playwright-managed Chromium process for a run and creates an isolated browser context and page for each case. Run-wide locale and headless settings use Stagehand defaults when omitted. Each case inherits the run's viewport and time zone, and may override either setting. Headless mode is run-wide because it is selected at browser launch.

The public entry point exports `startBrowserRun`. It returns a run with `createCaseSession` and `close` methods. Each case session exposes `navigate`, which accepts an absolute HTTP/HTTPS URL and uses `domcontentloaded` with a 30-second timeout by default; the supported `waitUntil` and timeout settings can be overridden. It also exposes `resolveLocator`, which accepts one schema locator (`role`, `label`, `css`, or `xpath`) and returns its unique Playwright locator. Role and label names are matched exactly. A missing match is retried up to three times, with one-second gaps, within the supplied timeout; the default is 30 seconds. The timeout is divided across the locator waits after reserving retry gaps. Multiple matches fail immediately. The `click` method uses the same locator rules and a 30-second default timeout; locator lookup and Playwright click actionability share that timeout budget. Scrolling is enabled by default, and `scrollIntoView: false` makes Playwright fail if the target is outside the viewport. The `type` method uses the same locator and timeout rules, enters characters sequentially with Playwright's default zero delay, and shares its timeout between locator lookup and typing. The `fill` method sets a field's value directly using the same locator and timeout rules. `selectOption` chooses exactly one option by its value or visible label and uses the same locator, timeout, and scroll rules. `assertText` compares inner text, `assertHtml` compares inner HTML, and `assertValue` compares the control's input value. All three compare exact, case-sensitive strings selected for the run locale, and share one timeout between locator resolution and reading the value. The `scrollIntoView` option applies to interactions, not assertions. Case sessions also expose `runWaitList`, which runs wait items sequentially: locator waits poll once per second for exactly one match, page-state waits support `domcontentloaded` and `networkidle`, and fixed delays may last 1 to 30,000 milliseconds. Each item defaults to a 30-second timeout; a shorter timeout bounds the wait and causes a `WaitExecutionError` if it expires. `executeSteps(caseId, steps)` dispatches validated `navigate`, `click`, `type`, `fill`, `selectOption`, `assertText`, `assertHtml`, and `assertValue` steps in sequence; interaction steps run their `before` and `after` waits. It throws a `StepExecutionError` with the case ID, zero-based step index, action, and original cause when a hard assertion or another step fails. Soft assertion mismatches, missing or ambiguous locators, and text/HTML/value-read timeouts are returned with case ID, step index, expected value, and a diagnostic; actual content is included when available, and later steps continue. Axe scanning, integration with plan loading, result records, and case/run outcome aggregation are not implemented by this dispatcher. Close each case session when its case finishes, and call the run's `close` method in a `finally` block. Closing the run waits for in-flight case setup, rejects sessions that have not finished setup when shutdown starts, closes any active case sessions, and then closes Chromium. Concurrent run `close` calls await the same cleanup.

`assertValue(locator, expected, options)` compares the control's input value exactly, using the run locale. Options accept `timeout` and an optional `associatedLabel` expected-value object. The label check uses the control's standard HTML `labels` association (wrapping labels or `for` attributes), compares visible text exactly, and shares the value assertion's timeout. A missing, ambiguous, mismatched, or timed-out label check returns an `AssociatedLabelFailure`; a successful check returns `undefined`. Value failures throw through the direct API. Through `executeSteps`, value assertions are hard by default and support `soft: true`; label failures are always soft and carry `check: "associatedLabel"`. A hard value failure stops the step before the label check. A soft value failure still permits the label check within the remaining timeout, so one step can return both a value failure and a label failure. Unexpected browser errors remain hard failures.

The `assertValue` slice builds and passes all 81 runner-core tests locally on Windows with the pinned toolchain. Tests use Playwright doubles, including checks for shared timeout budgets and label outcomes; dev-container, real-browser, and current CI verification of this slice remain outstanding.

Build and test from the repository root:

```sh
npm test --workspace @stagehand/runner-core
```

The tests import the public package name and replace the Playwright launch method with small test doubles, so they do not require a downloaded browser. Dispatcher tests cover ordered `navigate`/`click`/`type`/`fill`/`selectOption`/`assertText`/`assertHtml`/`assertValue` execution, interaction wait lists, scrolling, timeout handling, failure context, and the no-scroll viewport rule. The suite includes 19 added `assertValue` and associated-label test cases, alongside the existing 62 tests.
