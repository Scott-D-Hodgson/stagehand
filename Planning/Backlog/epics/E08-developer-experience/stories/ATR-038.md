# ATR-038 — Enforce agent containment through runtime controls

**Epic:** E08  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a Stagehand maintainer, I want AI-agent activity restricted to an approved development environment so that host resources and credentials are protected.

## Description

Document and configure supported sandbox/runtime controls; repository text alone is not treated as enforcement.

## Acceptance criteria

### AC-1 — Boundary documented

Stagehand documents which runtime/sandbox enforces the container boundary.

### AC-2 — Least privilege

The setup avoids privileged mode and unnecessary host mounts.

### AC-3 — Credentials

Host credentials and production secrets are not mounted by default.

### AC-4 — Network policy

Required network access and restrictions are documented and applied where supported.

### AC-5 — Limits stated

Stagehand clearly states when a particular agent runtime cannot enforce the desired boundary.

## Dependencies

- ATR-036
- ATR-037

## Verification

- Add unit, integration, or manual verification appropriate to the acceptance criteria.

## Notes

- A dev container alone is not a security boundary if the agent has unrestricted host access.
