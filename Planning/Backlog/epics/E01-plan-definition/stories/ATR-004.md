# ATR-004 — Configure reports and accessibility

**Epic:** E01  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want to configure JSON output and enable accessibility scanning in the plan so that each run produces the selected diagnostics.

## Description

Support JSON result output and its destination, plus optional axe scanning. JSON is the only MVP report format; conversions to JUnit XML, HTML, or other formats are deferred.

## Acceptance criteria

### AC-1 — JSON result format

The MVP produces the versioned JSON result.

### AC-2 — Output destination

The JSON output path is configurable and output path errors are reported.

### AC-3 — Accessibility switch

Axe scanning is disabled when omitted. It can be enabled or disabled at plan level; a case can override that setting.

When requesting axe scanning for a run, provide a companion optional list of rule tags to control scan scope. A non-empty list restricts scanning to rules matching any selected tag. An omitted or empty list applies no tag filter and uses axe's default rule selection. This means all default-enabled rules, not forcibly enabling experimental or other disabled rules. This is an accepted requirement; the tag option is not implemented in the current schemas or runner. Exact CLI flags and any case-level tag override remain to be defined.

### AC-4 — Scan behaviour

When enabled, axe scans run after every completed step, including a step with a failed assertion if the browser remains usable. Findings remain attached to their case and are grouped by URL and violation description within that case; already recorded problematic markup is ignored and newly observed markup is added to that finding.

### AC-5 — Accessibility results

Findings are represented in the result model and included in supported reports. Each finding includes its page URL and available affected-node details. The case's effective settings record `enabled`, `failOnViolation`, and the effective scan-tag scope so readers can distinguish a restricted assessment from axe's default scope. The exact representation belongs to the pending result-model extension.

### AC-6 — Accessibility status policy

The `failOnViolation` setting defaults to `false`. Plan configuration may set the policy, and case configuration may override it. An axe scan execution error remains distinct from a detected violation; M6 defines how each affects case/run outcomes and continuation.
