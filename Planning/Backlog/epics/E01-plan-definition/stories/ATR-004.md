# ATR-004 — Configure reports and accessibility

**Epic:** E01  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want to configure JSON output and enable accessibility scanning in the plan so that each run produces the selected diagnostics.

## Description

Support JSON result output and its destination, plus optional axe scanning. JSON is the only MVP report format; conversions to JUnit XML, HTML, or other formats are deferred.

## Acceptance criteria

### AC-1 — JSON result format

The MVP produces the versioned JSON result.

### AC-2 — Output destination

The JSON output path is configurable and output path errors are reported.

### AC-3 — Accessibility switch

Axe scanning is disabled when omitted. It can be enabled or disabled at plan level; a case can override that setting.

### AC-4 — Scan behaviour

When enabled, axe scans run after every completed step, including a step with a failed assertion if the browser remains usable. Within one run, findings are grouped by URL and violation description; already recorded problematic markup is ignored and newly observed markup is added to that finding.

### AC-5 — Accessibility results

Findings are represented in the result model and included in supported reports.

### AC-6 — Accessibility status policy

The `failOnViolation` setting defaults to `false`. Plan configuration may set the policy, and case configuration may override it. An axe scan execution error remains distinct from a detected violation; M6 defines how each affects case/run outcomes and continuation.
