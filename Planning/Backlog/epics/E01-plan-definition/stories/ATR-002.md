# ATR-002 — Load and validate a test plan

**Epic:** E01  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want the runner to load and validate a JSON plan before execution so that malformed plans fail early and clearly.

## Description

Support loading from a file for CLI execution and accepting an already-parsed plan through the reusable API.

## Acceptance criteria

### AC-1 — Read plan

The CLI can read a plan from a specified file path and resolve referenced case JSON files. References are portable relative paths based on the plan file's directory; absolute paths and references that resolve outside that directory are rejected. Symlinks, junctions, and other filesystem links are followed only when their canonical target remains inside the canonical plan directory. Each case file represents one executable case; a case file may also define a named data set that is promoted into the plan's data-set collection. Case IDs are unique within a plan.

### AC-2 — Invalid JSON

Malformed JSON produces a clear error and nonzero CLI exit code.

### AC-3 — Schema validation precedes execution

The plan is fully validated before a browser is launched.

### AC-4 — File errors are actionable

Unreadable or missing files produce an actionable error without a misleading test-failure report.

### AC-5 — Validate referenced case files before execution
Every referenced case file is resolved and validated before browser startup. Missing, unreadable, invalid, or unsupported case files identify the reference and provide an actionable error. References, including those traversing filesystem links, that resolve outside the canonical plan directory are rejected. A plan with an unresolved or duplicate case reference is invalid and cannot proceed to execution. The browser editor uses the same logical references while importing/exporting user files, without requiring direct filesystem access. Folder import preserves relative paths for matching files to references. An editor may save an invalid plan as a draft, but must not present it as valid until all references are resolved and unique.
