# ATR-001 — Define the versioned JSON test-plan schema

**Epic:** E01  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want a documented, versioned test-plan schema so that plans can be validated and interpreted consistently by the editor and runner.

## Description

Define a shared, versioned JSON Schema document for a test plan: the plan contains shared steps, executable cases, and named data sets. A case is one executable test case with steps; its JSON file may also contribute a named data set that is made available at plan scope. The schema also covers plan/case configuration, nested variables, loop constructs and limits, localization of descriptions and expected assertion values, accessibility failure policy, execution timeout/duration/concurrency/cancellation options, and supported step/action structures.

## Acceptance criteria

### AC-1 — Version is explicit

Every plan declares a schema version, and the validator selects the corresponding schema.

### AC-2 — Required fields are checked

Missing required fields, invalid types, unknown actions, and invalid configuration values produce actionable validation errors.

### AC-3 — Unsupported versions are rejected

A plan with an unsupported schema version is rejected before browser execution.

### AC-4 — No silent instruction loss

Unsupported instructions are never silently ignored.

### AC-5 — Schema has automated tests

Valid and invalid fixtures verify the schema and validation behaviour.

## Dependencies

- None identified.

## Verification

- Schema tests cover required fields, types, enumerations, and unsupported versions.

## Notes

- Keep arbitrary executable JavaScript out of JSON plans in the initial release.
