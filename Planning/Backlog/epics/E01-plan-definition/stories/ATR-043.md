# ATR-043 — Remove timeout from fixed-delay waits

**Epic:** E01 — Plan definition and configuration  
**Status:** Proposed  
**Priority:** Later  
**Release:** Later

## User story

As a test author, I want a fixed-delay wait to specify only its delay so that the plan format does not expose a redundant timeout setting.

## Description

The version 1 case schema currently permits an optional `timeout` beside `delay`. Runner-core treats that timeout as an upper bound for the delay and fails if the requested delay exceeds it. Since fixed delays are capped at 30,000 ms and the current default wait timeout is also 30,000 ms, the field is not useful to ordinary authors and is intentionally hidden by the editor.

Remove this field only through a deliberate versioned-contract change. The change must cover the case schema, runner wait definition and execution, fixtures, editor import/export behaviour, and compatibility or migration for existing version 1 documents.

## Acceptance criteria

### AC-1 — Revised delay-wait shape

**Given** the next supported plan-contract version  
**When** an author creates a fixed-delay wait  
**Then** it accepts a bounded `delay` value and does not accept a `timeout` property.

### AC-2 — Other wait timeouts remain available

**Given** locator and page-state waits  
**When** their schemas are validated  
**Then** their optional timeout behaviour remains supported.

### AC-3 — Compatibility is explicit

**Given** an existing version 1 case containing a delay-wait timeout  
**When** it is opened or executed under the revised contract  
**Then** the migration, continued-version-1 support, or rejection behaviour is documented and tested rather than silently discarding the value.

- The editor may preserve an imported version 1 delay-wait timeout without presenting it as an editable setting until this contract change is delivered.
