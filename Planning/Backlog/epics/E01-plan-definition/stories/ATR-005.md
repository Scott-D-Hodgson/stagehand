# ATR-005 — Support localized test-plan content

**Epic:** E01  
**Status:** Proposed  
**Priority:** Should  
**Release:** MVP

## User story

As a test author, I want user-facing test and step descriptions to support multiple languages so that teams can author and review tests in their preferred language.

## Description

Keep stable identifiers and separate localized descriptions from machine-readable action instructions.

## Acceptance criteria

### AC-1 — Localized descriptions

Test names, step descriptions, assertion descriptions, and relevant display text can provide translations.

### AC-2 — Stable identity

Plan and case identifiers remain stable between language variants. Steps are identified by case ID and their position in the case's step sequence; result documents represent this position with a zero-based index. Step position does not depend on translated text.

### AC-3 — Fallback

A documented fallback language is used when a localized description is unavailable. Assertion expected values have a default value, with optional locale-specific overrides as described under AC-6.

### AC-4 — Browser locale is independent

The language of plan descriptions can differ from the browser locale.

### AC-5 — Reports preserve chosen text

Reports use the resolved description language for the run.

### AC-6 — Localized expected values
Assertions provide an `expected` object with a required string `default` value and optional string `locales` overrides keyed by BCP 47 locale tags. The runner canonicalizes locale keys before matching the run-wide locale and uses the matching override when present; otherwise, it uses `default`. Locale keys that canonicalize to the same tag are invalid.
