# ATR-026 — Override configuration through CLI arguments

**Epic:** E04  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test operator, I want CLI options to override plan configuration so that one plan can be reused across run environments.

## Description

Support CLI overrides for plan-level and case-level configuration, including browser/run settings, case selection or options as finalized, variables, JSON report output path, accessibility scanning/failure policy, execution timeouts, duration thresholds, concurrency, and run-time dataset selection. The exact flag/argument shape remains to be designed.

## Acceptance criteria

### AC-1 — Supported overrides

Each documented setting can be overridden from the CLI.

### AC-2 — Precedence

At each configuration scope, an explicit CLI value overrides the corresponding JSON value, which overrides the documented default. Plan-level values flow to cases unless a case JSON or case-targeted CLI override replaces them. Variable lookup follows step > case > plan; a CLI value replaces the file value at the scope to which that CLI option applies.

### AC-3 — Source plan unchanged

Overrides do not modify the input JSON file.

### AC-4 — Effective configuration

Result metadata identifies effective non-secret settings.

### AC-5 — Invalid override

Invalid options fail clearly before execution where possible.

## Data-set selection scope

Runtime data-set selection is per case. Without a selection for a case, use that case's declared default. One data-set name applied to every case in the run is deferred beyond MVP. Exact CLI flag/argument syntax remains later CLI design; this decision does not implement flags.

CLI-supplied input overrides are resolved before execution and do not introduce variable reassignment while a case runs. Unknown selected data-set names fail before browser startup; omitted selections still use each case's default.
