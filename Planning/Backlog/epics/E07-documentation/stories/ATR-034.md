# ATR-034 — Maintain canonical Markdown documentation

**Epic:** E07  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a Stagehand contributor, I want the user guide and reference documentation stored as Markdown in Git so that documentation can be reviewed and reused.

## Description

Organise setup, authoring, configuration, integrations, troubleshooting, architecture, and contribution guidance.

## Acceptance criteria

### AC-1 — Topic structure

Documentation covers installation, authoring, configuration, CLI, reports, accessibility, integrations, and development.

### AC-2 — Source is in repo

Canonical Markdown files are version-controlled in the monorepo.

### AC-3 — Examples are safe

Examples use synthetic values and no real secrets.

### AC-4 — Documentation review

Behaviour-changing work updates affected documentation.

## Dependencies

- None identified.

## Verification

- Add unit, integration, or manual verification appropriate to the acceptance criteria.
