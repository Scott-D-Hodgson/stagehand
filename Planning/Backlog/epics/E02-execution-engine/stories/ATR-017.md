# ATR-017 — Resolve protected values from environment variables

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want plans to reference protected values by environment-variable name so that secrets do not need to be stored in JSON.

## Description

Support external secret/value references, redaction, and validation before use.

## Acceptance criteria

### AC-1 — Reference only

A variable's default or locale-variant value uses {"env":"TEST_PASSWORD"}: the plan stores the environment-variable name, not the protected value. Action/assertion inputs can then use a whole-field {"var":"password"} reference.

### AC-2 — Runtime resolution

The planned runner resolves the reference from the process environment before browser startup; it does not refresh or reassign the fixed input during execution. Environment variables are the only supported secret source in the initial release.

### AC-3 — Missing secret

A missing required effective environment variable fails validation before any browser is started and reports its name without disclosing a value. Unselected data sets and overridden definitions do not require their environment values to be present. A present empty value counts as supplied.

### AC-4 — Redaction

Resolved protected values are redacted from logs, errors, reports, retained assertion evidence, and retained axe evidence. This includes markup, URLs, selectors, summaries, and related-node information, as well as exposed retained scan records; necessary unredacted execution values remain private to execution.

### AC-5 — No accidental export

The effective configuration and exported plan do not contain resolved secret values.

## Dependencies

## Verification

- Add unit, integration, or manual verification appropriate to the acceptance criteria.

## Effective localized protected inputs

Validate document structure throughout the loaded plan, but resolve environment values only for effective execution inputs after scope/data-set selection. A missing environment variable in an unselected data set or overridden definition does not block the run. Missing required effective values fail before browser startup. An existing environment variable with empty text is supplied, not missing; preserve it for negative test scenarios. Defaults and optional locale variants may select protected environment references. Only the effective selected reference is resolved. Redaction must cover retained evidence without treating an empty protected value as a match at every position in output.

Current runner-core history exposes original raw scan references and does not redact them. M5 must reconcile this with the accepted redaction requirement before real protected inputs are supported; existing evidence APIs are not secret-safe today. Safe redacted representations must also satisfy result-model field formats, including URLs. Detailed redaction boundaries/encoding tests remain contract-design work, not a shipped guarantee.
