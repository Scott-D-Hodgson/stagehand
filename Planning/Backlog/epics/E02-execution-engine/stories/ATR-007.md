# ATR-007 — Expose a reusable asynchronous execution API

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As an integrator, I want a reusable asynchronous library API so that different entry points can execute the same test plans without duplicating runner logic.

## Description

The library accepts a validated or parseable plan and options and returns a structured result independent of CLI output.

## Acceptance criteria

### AC-1 — Public API

A documented async API accepts plan input and execution options.

### AC-2 — Structured result

The API returns a typed result containing status, tests, steps, diagnostics, and summary.

### AC-3 — CLI independence

The core library does not parse CLI arguments or print CLI-formatted output.

### AC-4 — Repeated use

Repeated calls do not leak unintended state between runs.

### AC-5 — Errors are classified

Validation, test, and runner-level failures have documented semantics.

## Dependencies

- None identified.

## Verification

- Unit tests exercise the API with valid plans, invalid plans, and repeated calls.
