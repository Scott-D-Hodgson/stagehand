# ATR-008 — Execute supported Playwright browser actions

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want declarative browser actions so that I can describe end-to-end flows without writing a separate test program for each flow.

## Description

Implement the initial documented action and assertion vocabulary for browser-based tests. Prefer user-facing role and label locators; also allow CSS selector and XPath escape hatches. The initial MVP scope is intended to be authorable by a non-technical tester in the Phase 2 Vue editor.

## Acceptance criteria

### AC-1 — Locator choices

The author can identify elements with preferred user-facing role or label locators, with CSS selector and XPath escape hatches for cases those locators cannot express. A locator is an object with one strategy: `{"role":"button","name":"Sign in"}`, `{"label":"Email"}`, `{"css":"#submit"}`, or `{"xpath":"//button"}`. Role and label names match exactly. A role locator may include a `name` to identify its accessible name. If an action locator matches multiple elements, the step fails immediately; Stagehand must not choose one arbitrarily. If it matches none, the runner waits for a match on each attempt, up to three attempts total by default, with one-second gaps between attempts. Attempts share the action's timeout: reserve the gaps between attempts, then divide the remaining timeout as evenly as possible among the locator waits. For example, a 30-second timeout allows three waits of about 9.3 seconds each and two one-second gaps. If the timeout expires, no further attempt starts. Locator waits in `before`/`after` lists use the separate bounded-wait rule in AC-3.

### AC-2 — Navigation

Each step is an object with an `action` field. A `navigate` step supplies `url` and may set `waitUntil`; when omitted, `waitUntil` is `domcontentloaded`. The supported post-navigation states are `domcontentloaded` and `networkidle`. Actions and waits default to a 30-second timeout and may override it with a positive integer `timeout` value in milliseconds. Reload, back, and forward are deferred to [ATR-042](ATR-042.md).

### AC-3 — Interaction

Support the `click`, `type`, `fill`, and `selectOption` actions. Each supplies a `locator`; `type` also supplies `text`, and `fill` supplies `value`. `type` enters characters; `fill` sets the field value directly. `selectOption` supplies exactly one of `value` or visible `label`.

The click item in the request is treated as the same click operation listed here, not a second distinct action. Add distinct click variants (such as double-click) only if separately specified.

Interactions may include `before` and `after` lists. Items run in list order before or after the interaction, respectively. A locator wait uses `{ "waitFor": { "role": "button", "name": "Continue" } }`; a page-state wait uses `{ "waitForState": "networkidle" }` or `{ "waitForState": "domcontentloaded" }`; and a fixed delay uses `{ "delay": 500 }`, measured in milliseconds. Wait items may also set a positive integer `timeout` in milliseconds. Waits are bounded. A `waitFor` locator is checked once per second until exactly one match appears or its single timeout budget expires; multiple matches fail immediately. Fixed `delay` values are integers from 1 to 30,000 milliseconds.

Interactions scroll the target into view automatically by default. A step may set `scrollIntoView` to `false` to turn this off; there is no separate scroll action.

The default timeout for an action or wait is 30 seconds; an action or wait may override it. Do not assume arbitrary delays or waits are always appropriate.

### AC-4 — Waiting

Support bounded waits for selectors and documented page states needed by navigation and interaction options. Standalone URL waits are deferred with the extended action vocabulary in [ATR-042](ATR-042.md).

### AC-5 — Assertions

Support `assertText` (inner text), `assertHtml` (inner HTML), and `assertValue` (input value), each with a `locator` and an `expected` object. The object has a required string `default` value and may have a `locales` object keyed by BCP 47 locale tags, with string values. Locale keys are canonicalized before matching the run-wide locale; locale keys that canonicalize to the same tag are invalid. For example, `{ "default": "Sign in", "locales": { "fr-CA": "Se connecter" } }`. The run-wide locale selects an override when available and otherwise uses `default`. Comparisons are exact and case-sensitive in the MVP; a future `contains` comparison is deferred to [ATR-042](ATR-042.md). Assertions are hard by default; `soft: true` records a soft failure. The continuation and status effects of hard and soft failures are defined by [ATR-010](ATR-010.md) and M6. An `assertValue` may include `associatedLabel` with its own `expected` object to check the associated label's visible text. This optional check is exact and case-sensitive and is always soft. Resolve labels using standard HTML associations such as a wrapping `<label>` or its `for` attribute. If no associated label exists or multiple associated labels make the association ambiguous, that label check fails softly. Other assertion types, including visibility, enabled/disabled, checked state, attributes, URL, and page title, are deferred to [ATR-042](ATR-042.md).

### AC-6 — Step results

Each action produces a structured step outcome and duration. Step identity in diagnostics and results uses the case ID plus the step's zero-based index in its sequence; authors do not assign step IDs.

### AC-7 — Diagnostics

Playwright errors are translated into useful diagnostics without losing relevant technical detail. Timeout and assertion diagnostics include the case ID, step position, action, relevant locator, and timeout value; assertion failures also include expected and actual values where available. M5 defines redaction if expected values later support secrets.
