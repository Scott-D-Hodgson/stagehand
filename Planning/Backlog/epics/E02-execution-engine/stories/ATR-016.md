# ATR-016 — Resolve nested variables and runtime values

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want plan, case, and step variables with predictable overrides so that I can reuse the same plan with different data without duplicating it.

## Description

Support plan-, case-, and step-level variables. A narrower scope shadows a wider scope: step overrides case, and case overrides plan. CLI-provided values override file-provided values at the corresponding plan or case scope. Shared steps read the calling case's variable context; shared steps do not declare parameters or their own variable defaults. Any variable a shared step needs must be defined by the case or a named data set imported into that case. Environment-variable references are the only secret source in the initial release.

## Acceptance criteria

### AC-1 — Nested scope lookup

Plan variables are visible to cases unless overridden by case variables; case variables are visible to steps unless overridden by step variables.

### AC-2 — CLI overrides at matching scope

CLI options can override plan-level and/or case-level configuration and variables. A CLI value wins over a file value at the same scope, while normal nested shadowing remains step over case over plan.

### AC-3 — Shared-step variable context

Shared steps resolve variables from the calling case's normal variable context. They cannot declare parameters or private variable defaults. Shared-step groups cannot call other shared-step groups.

### AC-4 — Named data sets

A plan may define default and named data sets. A case JSON file may contribute a named data set to the plan-level collection and name the set it intends to use by default. At run time, a selected set is imported into that case's variables for that execution; a run-time set selection replaces the case's default selection, and its values take precedence over same-named case-default values. If both specify a set for that case, the run-time selection wins. Define behaviour for unknown set names and duplicate definitions in the plan-level collection.

### AC-5 — Case isolation

Each case has isolated mutable state; one case's mutations do not leak to another case.

### AC-6 — Unknown and missing values

Unknown references and unresolved required values produce actionable errors before browser execution when they can be resolved statically.

### AC-7 — No arbitrary execution

Variable values do not enable arbitrary JavaScript execution from a plan.
