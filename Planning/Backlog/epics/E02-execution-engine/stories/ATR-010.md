# ATR-010 — Handle hard and soft assertion failures

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test author, I want assertions to support hard and soft failure modes so that functional failures can stop a test while non-blocking checks still collect useful regressions.

## Description

Hard assertions stop the current test. Soft assertions are recorded as failures and allow subsequent eligible steps to continue.

## Acceptance criteria

### AC-1 — Hard assertion default

An assertion is hard unless explicitly configured as soft.

### AC-2 — Hard failure stops test

A failed hard assertion marks the step failed and stops the current test.

### AC-3 — Soft failure continues

A failed soft assertion is recorded and execution continues with the next eligible step.

### AC-4 — Soft failure remains a failure

Any failed required soft assertion causes the test result to be failed, even if later steps pass.

### AC-5 — Expected and actual values

Where available, the failure records expected and actual values.

### AC-6 — Independent tests continue

Recoverable failure in one test does not prevent independent tests from running.

### AC-7 — Runner safety

Continuation is not attempted when a runner-level failure makes it unsafe.
