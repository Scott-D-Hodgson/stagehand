# ATR-014 — Control execution timeouts and concurrency

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test operator, I want execution limits so that stalled actions and excessive parallelism do not destabilize the runner.

## Description

Use bounded plan/case execution with a default maximum timeout of 10 minutes, overridable by plan and case configuration. Support configurable run and case duration thresholds that fail the corresponding execution when exceeded. Each case gets an isolated Playwright browser context within a shared browser instance; run up to five cases/contexts in parallel by default, with a plan-configurable limit. Operators can cancel a run.

## Acceptance criteria

### AC-1 — Plan and case timeout

The active case execution timeout defaults to 10 minutes. It starts when the case begins executing its steps, excludes time waiting for a concurrency slot, browser/context startup, and cleanup, and can be overridden by plan and case configuration. Define how the plan-level active-execution timeout behaves with parallel cases.

### AC-2 — Startup timeout

Browser startup is bounded and failures are reported.

### AC-3 — Case parallelism

Each case receives an isolated Playwright browser context; cases share the browser instance/process. Up to five cases/contexts run concurrently by default; the plan may specify a concurrency limit. CLI override behaviour follows the configuration precedence rules.

### AC-4 — Timeout outcome

Timeouts produce a failed step/test outcome and useful diagnostics.

### AC-5 — Limits are explicit

Timeouts do not claim to forcibly terminate arbitrary non-cooperative in-process code.

### AC-6 — Duration thresholds

The operator may configure plan and case duration thresholds; exceeding the applicable threshold marks the affected execution failed and records actual duration and threshold.

### AC-7 — Cancellation

The operator can cancel a run. Cancellation stops scheduling new cases, requests active case/browser work to stop, cleans up resources, and records a cancelled outcome distinct from a test assertion failure.

### AC-8 — Timing

Results record total plan-run duration and each case duration, including parallel execution without summing overlapping case durations as elapsed run time.
