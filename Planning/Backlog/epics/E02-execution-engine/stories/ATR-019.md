# ATR-019 — Run axe accessibility scans after each step

**Epic:** E02  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a test operator, I want optional axe scans after each completed step so that accessibility issues are detected throughout functional end-to-end runs.

## Description

When enabled for a plan or case, run an axe scan after every completed step. Within one run, group findings by URL and violation description; within each group, append only problematic markup not already seen. Report findings separately from functional assertions.

## Acceptance criteria

### AC-1 — Explicit setting

Plan configuration controls whether scanning is enabled by default; case configuration may override it.

### AC-2 — Scan each step

When enabled, scans run after every completed step.

### AC-3 — Findings and de-duplication

Findings include URL, rule ID, impact, description, and affected element/problematic markup information where available. For the same URL and violation description, repeated markup is ignored and newly observed markup is added to the existing finding.

### AC-4 — Independent outcome

Accessibility findings are recorded separately from soft assertion failures and functional assertions.

### AC-5 — Failure policy

Violations do not fail a case by default. Plan configuration can define the default policy and case configuration can override whether findings fail that case. An axe execution error is distinct from a detected violation and follows the runner error policy.

### AC-6 — Report integration

Supported reports include accessibility findings and preserve their distinct classification.
