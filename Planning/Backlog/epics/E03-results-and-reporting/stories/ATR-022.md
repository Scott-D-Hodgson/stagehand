# ATR-022 — Generate JUnit-compatible XML reports

**Epic:** E03  
**Status:** Proposed  
**Priority:** Later  
**Release:** Later

## User story

As a CI/CD maintainer, I want XML test output so that Azure DevOps can publish runner results as test results.

## Description

Generate a documented JUnit-compatible XML dialect and validate it against Azure DevOps test-result publishing.

## Acceptance criteria

### AC-1 — XML output

The selected XML format produces well-formed XML.

### AC-2 — Test outcomes

Each case is represented as a reportable test with its name/ID, outcome, elapsed duration, and failure detail where applicable, in the form Azure DevOps can publish.

### AC-3 — Soft assertions

Soft assertion failures are represented without losing their classification in the richer JSON result.

### AC-4 — Accessibility findings

Accessibility findings are represented according to the documented reporting policy.

### AC-5 — Azure DevOps verification

An example pipeline can publish the generated XML and display test outcomes.

## Dependencies

- ATR-020
- ATR-004

## Verification

- Add unit, integration, or manual verification appropriate to the acceptance criteria.

## Notes

- Azure DevOps maps JUnit `<failure>` and `<error>` cases to failed tests and `<skipped>` cases to not-executed. Preserve the more precise Stagehand outcome in JSON and verify the conversion in an example pipeline.
- Confirm the exact JUnit dialect and Azure DevOps task compatibility before implementation; define which Azure DevOps statuses and fields must be visible.
