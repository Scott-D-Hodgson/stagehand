# ATR-020 — Define the versioned result contract

**Epic:** E03  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As an integration developer, I want a stable result contract so that reports and integrations can consume outcomes consistently.

## Description

Define overall run, case/test, step, assertion, accessibility, diagnostics, timing, cancellation, and artifact structures, including duration and screenshot references.

The MVP produces one JSON result per run, with a run-level summary and one record per case. Each case record includes its stable ID/name, outcome, duration, failure/error detail, and effective non-secret configuration. JSON retains step/assertion diagnostics and accessibility findings. Artifact references are supported by the result contract when artifact capture is added later. JSON is the sole MVP output format.

## Acceptance criteria

### AC-1 — Versioned result

Results declare a schema/version.

### AC-2 — Distinct outcomes

Functional status, soft assertion failures, accessibility findings, and runner errors can be distinguished.

### AC-3 — Traceability

Results retain test/step IDs, timing, and loop context where relevant.

### AC-4 — Safe content

Secrets are excluded or redacted.

### AC-5 — Compatibility

Schema evolution and compatibility policy are documented.

### AC-6 — Run and case fields

The run summary includes overall outcome, start/end timing and elapsed duration, and case outcome counts. Each case includes stable identity, outcome, elapsed duration, and relevant failure/error information. Use `passed` (case completed successfully), `failed` (a functional assertion failed), `cancelled` (execution was interrupted by cancellation), and `error` (the runner could not execute or complete the case due to an operational error). Do not add `skipped` to the MVP contract unless a feature that deliberately omits cases is added; case selection is currently Later. Document run-level aggregation rules.

### AC-7 — Artifacts and detailed JSON

JSON preserves step/assertion diagnostics, accessibility findings, effective non-secret configuration, and artifact references, including failure screenshots where captured.
