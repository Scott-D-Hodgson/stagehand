# ATR-029 — Provide a local-first Vue plan editor

**Epic:** E05  
**Status:** Proposed  
**Priority:** Must  
**Release:** MVP

## User story

As a non-technical test author, I want a user-friendly visual editor so that I can create and maintain JSON-backed test plans without manually editing JSON.

## Description

Build a client-side Vue SPA for modern browsers, with static hosting, that edits user-owned plans and does not maintain a central repository. The initial editing experience is form-based; a raw JSON editor is deferred.

## Acceptance criteria

### AC-1 — Client-side editing

Core editing and validation work without a product-owned backend.

### AC-2 — Import plan

A user can select/import a local JSON plan and its referenced case JSON files. Folder import preserves paths relative to the plan so files can be matched to its portable references.

### AC-3 — Form-based editing

A user can create and edit plan and case configuration through controlled forms without manually editing JSON.

### AC-4 — Shared plan features

Before CLI delivery, the editor can author variables and shared steps, and can edit localized expected assertion values for different browser cultures.

### AC-5 — No automatic upload

Plans are not uploaded to a central service as part of ordinary editing.

### AC-6 — Hosting portability and offline use

The SPA can be statically hosted by Stagehand or deployed by a user organisation. MVP-supported editor browsers are current stable desktop Chrome and Edge on Windows. After the editor has loaded, an already-open editor remains usable offline; reliable cold-start/offline reopening is not required initially.

### AC-7 — Shared schema

The editor validates against the same versioned schema as the runner.

### AC-8 — Local file access

The editor supports user-owned files through upload/import and download/export in the MVP. Direct filesystem access is explicitly out of MVP scope and tracked by [TE-020](../../../technical-enablers/te-020-direct-filesystem-access-for-editor.md). Browser storage may provide convenience but does not replace user-owned files.

### AC-9 — Unresolved and duplicate case references

An imported plan with missing or duplicate case references is marked invalid until the references are resolved. The user may save/export it as a draft while it is invalid, but the editor must not present it as a valid plan.
