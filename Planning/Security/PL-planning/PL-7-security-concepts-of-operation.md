# PL-7 — Security Concepts of Operation

**Source:** [ITSG-33 Annex 3A, PL-7](https://www.cyber.gc.ca/en/guidance/annex-3a-security-control-catalogue-itsg-33).

## Control definition

Develop a security concept of operations (CONOPS) describing how the system will operate from an information-security perspective and update it at a defined frequency.

**Organisation-defined parameter:** review frequency. **Suggestion for review:** annually and when use, hosting, or data sensitivity changes.

## Supplemental guidance

The CONOPS may be part of the security plan or lifecycle documents. Changes should be reflected in plans, architecture, procurement, and engineering records.

## Plain-language metaphor

The security CONOPS is the “how we run this safely” guide, connecting the blueprint to daily operation.

## Stagehand and operator guidance

Describe intended Stagehand use, human oversight, task-plan handling, runtime boundaries, identity, target access, logging, artifact retention, updates, and incident/continuity procedures. Distinguish local editor use from CI or hosted execution because their risks differ.
