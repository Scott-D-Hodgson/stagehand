# RA-2 — Security Categorization

**Source:** [ITSG-33 Annex 3A, RA-2](https://www.cyber.gc.ca/en/guidance/annex-3a-security-control-catalogue-itsg-33#a314ra2).

## Control definition

Categorize system information under applicable requirements, record results and rationale in the security plan, and obtain approval from the authorizing official or delegate.

No organisation-defined parameters in the base statement.

## Supplemental guidance

Categorization considers impact to confidentiality, integrity, and availability and requires a clear system boundary and relevant information owners.

Like labelling a package by how serious it would be if lost, altered, or delayed.

## Stagehand and operator guidance

Operators must categorize plans, credentials, target data, browser artifacts, logs, and reports in their actual deployment; Stagehand does not assign classifications.
