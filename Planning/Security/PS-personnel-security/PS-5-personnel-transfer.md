# PS-5 — Personnel Transfer

**Source:** [ITSG-33 Annex 3A, PS-5](https://www.cyber.gc.ca/en/guidance/annex-3a-security-control-catalogue-itsg-33).

## Control definition

When people transfer or are reassigned, confirm continuing need for logical and physical access, make the defined transfer changes within a specified time, adjust privileges, and notify defined roles.

Suggested review: start access changes on the effective date; notify the manager, security, and IT within one business day.

## Supplemental guidance

Relevant actions can include reclaiming old credentials, changing privileges, and preserving access to official records from the former role.

## Plain-language metaphor

Like changing a key ring when someone moves to a new department.

## Stagehand and operator guidance

Stagehand users should review repository, CI, environment, and report permissions on role changes; product has no transfer workflow.

## Control enhancements

None listed.

## Assessment status

**Planned / not verified.** Stagehand implementation and deployment evidence must be assessed before assigning an implemented or compliant status. This summary is a paraphrase for planning, not an authorization decision.
