# SA-5 - Information System Documentation

**Source:** [ITSG-33 Annex 3A, SA-5](https://www.cyber.gc.ca/en/guidance/annex-3a-security-control-catalogue-itsg-33).

## Control definition

Obtain administrator documentation covering secure configuration, installation, operation, security functions, maintenance, and known risks of privileged functions. Obtain user documentation explaining security functions, safer use, and user responsibilities. When documentation is unavailable, document attempts to obtain it and take defined actions. Protect documentation according to risk and distribute it to assigned roles.

**Organisation-defined parameters:** actions when documentation cannot be obtained; recipients. **Suggestion for review:** document the gap and compensating operational instructions; provide admin guidance to operators and user guidance to authorized users.

## Supplemental guidance

Documentation helps personnel implement and operate security controls. Assess its quality and completeness, recreate essential missing material where needed, and protect vulnerability-related content in proportion to system sensitivity. Explain secure startup and recovery after interruption.

## Plain-language metaphor

Like the owner’s manual and emergency instructions that explain how to operate equipment safely.

## Stagehand and operator guidance

Maintainers should provide secure installation, configuration, update, and usage guidance, including treatment of plans, credentials, screenshots, traces, and reports. Operators should retain those instructions with restricted admin/security material where necessary.

## Control enhancements

(1) Functional properties of controls; (2) security-relevant external interfaces; (3) high-level design; (4) low-level design; and (5) source code are all **withdrawn and incorporated into SA-4(1) or SA-4(2)**, as identified in Annex 3A. They are not separate active requirements here.
