# SA-3 - System Development Lifecycle

**Source:** [ITSG-33 Annex 3A, SA-3](https://www.cyber.gc.ca/en/guidance/annex-3a-security-control-catalogue-itsg-33).

## Control definition

Manage the system under a defined lifecycle that incorporates security; define, document, and identify security roles; and integrate the organisation’s risk-management process into lifecycle activities.

**Organisation-defined parameter:** system development lifecycle. **Suggestion for review:** use a documented lifecycle with security review at design, implementation, release, and material-change milestones; name an accountable product security owner.

## Supplemental guidance

A well-defined lifecycle helps integrate security early and requires qualified security expertise among architects, engineers, and developers. Security awareness and enterprise architecture should support lifecycle decisions.

## Plain-language metaphor

Like checking building plans, construction, and inspections at each stage instead of waiting until move-in.

## Stagehand and operator guidance

Stagehand contributors should record threat assumptions and review changes affecting plans, browser control, secrets, artifacts, or releases. Operators should place Stagehand deployment and updates within their own system lifecycle and risk process.
