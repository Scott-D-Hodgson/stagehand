# Phase 3 — Execution engine and CLI

> **Living document:** All material in `Planning/` is generated by AI through discussions and direction from the developer; it is not written by hand. It provides structure, guidance, and context for ongoing development, and will be reviewed and updated periodically as Stagehand evolves.

Build the core browser execution path and its command-line interface:

- Playwright adapter and browser lifecycle.
- The initial browser action set: URL navigation with optional DOM-ready/network-idle waits; selector-based click, typing, direct value setting, and dropdown selection; and applicable bounded selector waits, delays, navigation-state waits, and scroll-into-viewport options.
- The initial assertion set: selector-based inner-text/inner-HTML comparisons and input-value comparisons, with an optional soft check of associated label text/HTML.
- Sequential step execution and failure handling.
- Hard/soft assertions and structured diagnostics.
- JSON reporting and CLI exit codes.
- Configuration overrides and environment-variable resolution.
- Case-level parallel execution with one isolated Playwright context per case in a shared browser instance. Start with five concurrent contexts by default and allow the plan to set the limit.
- Cancellation, 10-minute default active-case execution timeout (excluding queue wait, browser/context startup, and cleanup), configurable timeout overrides, and run/case duration thresholds that fail an execution when exceeded.
- Display a general non-blocking target-authorization/side-effects/cost warning before execution. Production-target identification and any production-specific acknowledgement are deferred to [TE-019](../../Backlog/technical-enablers/te-019-production-target-identification-and-warning.md).
