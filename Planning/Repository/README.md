# Repository structure

> **Living document:** All material in `Planning/` is generated by AI through discussions and direction from the developer; it is not written by hand. It provides structure, guidance, and context for ongoing development, and will be reviewed and updated periodically as Stagehand evolves.

This folder describes the shape of the Stagehand repository. The companion [structure](structure.md) document is a proposed monorepo footprint; some directories in it are future targets, not folders that exist today.

## Current top-level folders

- [`Planning/`](../README.md) - product backlog, roadmap, security planning, and work plans.
- [`Learning Plan/`](../../Learning%20Plan/README.md) - learning materials that prepare for Phase 1 work.

## Key folders in the proposed application layout

These application folders are described in `structure.md` and are intended as the future code and project layout:

- `apps/` - user-facing applications. The proposal includes a command-line app and a web app; API and desktop apps are later possibilities.
- `packages/` - reusable implementation modules shared by the applications, such as the execution engine, plan schema, results, reporters, and editor components.
- `examples/` - sample test plans that demonstrate how Stagehand plans are written and used.
- `docs/` - product and technical documentation for users and contributors.
- `website/` - the public project website, if the project needs one.
- `tests/` - broader tests that cover behaviour across packages or applications.
- `tools/` - repository maintenance and development utilities.
- `.devcontainer/` - development-container configuration for a repeatable local environment.

At the repository root, the proposal also calls for project guidance (`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, and `AGENTS.md`) and shared JavaScript/TypeScript configuration. Those files describe or configure the repository as a whole rather than belonging to one application package.

Treat the proposed layout as a guide for decisions, not evidence that every component has been built. The `structure.md` file says so too; a tidy drawing still doesn't make the road appear.
