# Repository structure

> **Living document:** All material in `Planning/` is generated by AI through discussions and direction from the developer; it is not written by hand. It provides structure, guidance, and context for ongoing development, and will be reviewed and updated periodically as Stagehand evolves.

This folder describes the shape of the Stagehand repository. The companion [structure](structure.md) document records the proposed monorepo footprint. The root npm workspace and initial CLI, web editor, and reusable-package folders exist. The plan-schema package contains initial plan and case schemas, synchronous schema validation, relative case-reference matching, and parsed-bundle case-schema and case-ID validation; filesystem loading, canonical containment, execution-related semantic validation, and application behaviour are not implemented. The other workspaces remain scaffolds, and other directories in the footprint remain future targets.

## Current top-level folders

- [`Planning/`](../README.md) - product backlog, roadmap, security planning, and work plans.
- [`Learning Plan/`](../../Learning%20Plan/README.md) - learning materials that prepare for Phase 1 work.
- `apps/` - initial CLI and Vue editor npm workspace scaffolds; no app behaviour is implemented yet.
- `packages/` - reusable-package npm workspaces; the plan-schema package has initial schema source, while the other packages remain scaffolds.
- [`Planning/Diagrams/`](../Diagrams/M1-component-dependency-graph.md) - editable diagrams that clarify proposed architecture and planning relationships.

## Application and package workspaces

These workspaces have `package.json` manifests. The plan-schema package also has JSON Schemas, a TypeScript public entry point, synchronous schema validators, a relative case-reference matcher, parsed-bundle validation for case schemas and ID uniqueness, package tests, and synthetic examples; file loading, filesystem containment, and execution-related semantic checks are not implemented. The other workspaces remain scaffolds with notes about their planned source entries and checks:

- `apps/cli/` - command-line app workspace.
- `apps/web/` - Vue editor app workspace.
- `packages/` - reusable workspaces for runner core, plan schema, plan engine, result model, and provisionally reporters.

The root `package.json` declares the npm workspaces, and the root `package-lock.json` records their dependency tree. API and desktop apps remain later possibilities.

## Other proposed folders

These paths are described in `structure.md` but have not been created as part of the initial workspace scaffold:

- `examples/` - sample test plans that demonstrate how Stagehand plans are written and used.
- `docs/` - product and technical documentation for users and contributors.
- `website/` - the public project website, if the project needs one.
- `tests/` - broader tests that cover behaviour across packages or applications.
- `tools/` - repository maintenance and development utilities.

At the repository root, the proposal also calls for project guidance (`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, and `AGENTS.md`) and shared TypeScript configuration. Those files describe or configure the repository as a whole rather than belonging to one application package.

Treat the proposed layout as a guide for decisions, not evidence that every component has been built. The `structure.md` file says so too; a tidy drawing still doesn't make the road appear.
