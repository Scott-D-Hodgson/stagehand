## Estimate basis

Estimates are **person-days of focused work** (roughly 6–7 productive hours), including drafting, implementation/configuration, and a basic self-review. They exclude waiting for reviews, learning time beyond the [Learning Plan](../../Learning%20Plan/README.md), meetings, and substantial rework from changed product decisions. One person-day is effort, not one calendar day. Ranges reflect uncertainty while architecture and contracts are still proposed.

The Phase 1 estimates assume one contributor familiar with Git and basic TypeScript/Node.js, working from the current backlog. Phase 1 now has its contracts, reusable browser-runner slices, and in-memory result adaptation; the CLI, editor, report-file writing, real-browser accessibility evidence, and later roadmap phases remain outside those original estimates. Phase 2 has its own estimate basis in the linked work plan.

## Completion criteria

Phase 1 is complete when:

- The repository has documented application/package boundaries and a working workspace foundation.
- The public GitHub repository routes all changes to `main` through pull requests, with the solo-phase self-review/check policy active and a documented path to require independent approval when collaborators are added.
- A new contributor can follow a pinned development setup and run the documented baseline checks.
- Contributor and agent guidance covers architecture, workflow, verification, and secret handling; any claimed runtime containment is backed by actual controls and its limits are documented.
- Versioned plan and result contracts are documented, represented in the repository, and have valid/invalid examples with clear validation behaviour.
- Browser settings, action vocabulary, assertion outcomes, variable/data rules, shared-step behaviour, error classes, and continuation policies are explicit enough for the execution engine to implement without guessing.
- Cross-cutting choices and unresolved issues are recorded, and the Phase 1 examples and checks agree with the contracts.

## Tracking guidance

For each milestone, keep its checklist current and link the review or decision record that demonstrates completion. If a decision changes the estimate or scope, update the milestone estimate and explain the change. These are initial planning estimates, not delivery commitments.
