## ITSG-33 control-family identifiers

These two-letter prefixes identify control families in the legacy ITSG-33 Annex 3A catalogue. They are identifiers as well as abbreviations; a code such as `AC-2` means control 2 in the Access Control family.

| Prefix | Control family |
|---|---|
| AC | Access Control |
| AT | Awareness and Training |
| AU | Audit and Accountability |
| CA | Security Assessment and Authorization |
| CM | Configuration Management |
| CP | Contingency Planning |
| IA | Identification and Authentication |
| IR | Incident Response |
| MA | Maintenance |
| MP | Media Protection |
| PE | Physical and Environmental Protection |
| PL | Planning |
| PS | Personnel Security |
| RA | Risk Assessment |
| SA | System and Services Acquisition |
| SC | System and Communications Protection |
| SI | System and Information Integrity |

## Planning identifiers

| Identifier | Meaning |
|---|---|
| E01–E09 | Epic identifiers in the backlog. The number distinguishes each epic. |
| M0–M7 | Work-plan milestone identifiers. M0 is repository bootstrap; M1–M7 decompose Phase 1. |
| ADR-### | Architecture Decision Record identifier. |
| ATR-### | Backlog story identifier prefix. The project materials do not assign an expansion to `ATR`; treat it as a stable ID, not as a defined phrase. |
| TE-### | Technical-enabler identifier. |
| ATR-XXX / TE-XXX | Placeholder identifiers in templates, not assigned backlog items. |
