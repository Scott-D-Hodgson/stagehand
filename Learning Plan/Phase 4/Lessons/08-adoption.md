# Lesson 8: Adoption readiness

> “What helps a new team decide whether Stagehand is ready for its work?” — Ada “Adoption Advocate” Armstrong, Developer

[← Previous: documentation](07-documentation.md) · [Phase outline](../README.md) · [Next: integration review →](09-integration-review.md)


Adoption needs a clear installation path, a small successful example, stated platform support, known limitations, troubleshooting, and an upgrade story. Honest boundaries build more trust than a long feature list.

The MVP begins with Windows runner support; Linux follows. Documentation should not imply broader verification than the project has evidence for.

## Try it

Draft a ten-minute first-run journey and list every assumption it makes about the reader's machine.

## You are ready when

You can assess readiness using evidence, support boundaries, and a repeatable onboarding path.
